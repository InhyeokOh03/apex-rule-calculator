# 엑셀 ↔ 웹앱 계산식 매핑

기준 파일: `downloads/ebook/ebook2_apex/Apex_드로우다운_출금_자동계산기_머니콤파스.xlsx`
(부록 B, 파일 버전 v1.0, 규정 확인일 2026-11-22)

## 시트 구성

| 시트 | 역할 |
|---|---|
| 사용안내 | 3분 사용법·시트 구성·EOD/Intraday 차이·자주 틀리는 네 가지 |
| 계좌 | 계좌 유형·시작 잔고·DD·최소 일 수익·크기·1포인트 가치 입력, 나머지 자동 |
| 기록 | 일별 손익 100세션. 마감 잔고·트레일링 임계값·버퍼 자동 |
| 출금 | 자격 일수·일관성·잔고 요건·회차별 상한 판정 |
| 상한표 | 회차별 상한(25K~150K × EOD/Intraday) + 계좌 크기별 기준값 |

## 계좌 시트 수식

| 셀 | 의미 | 수식 |
|---|---|---|
| B5 | 최초 임계값 | `=B3-B4` |
| B6 | 정지 임계값(PA 상한) | `=B3+100` |
| B7 | Safety Net | `=B4+100` |
| B8 | 최소 요청 잔고 | `=B3+B7+500` |
| B11 | 하루 개인 상한 | `=B4*0.25` |
| B16 | 입력값 점검 | 상한표 21~24행과 입력값 비교(`일치`/`확인 필요`) |

## 기록 시트 수식 (2행 기준, 이후 행은 이전 행 참조)

| 열 | 의미 | 수식 요지 |
|---|---|---|
| D | 마감 잔고 | `시작잔고 + SUM(실현손익) − SUM(출금액)` |
| E | 트레일링 임계값 | `MAX(이전 임계값, IF(EOD, 마감잔고, MAX(장중고점, 마감잔고)) − DD)` |
| F | 적용 임계값 | `MIN(임계값, 시작잔고+100)` — PA 정지선 캡 |
| G | 버퍼 | `마감잔고 − 적용 임계값` |
| H | 버퍼 비율 | `버퍼 ÷ DD` |
| K | 최대 리스크 | `계약수 × 손절폭 × 1포인트 가치` |

→ 웹앱은 일별 행 대신 **집계 입력**을 받습니다. 대응 관계:
`최고 잔고(HWM)` = EOD는 마감 잔고의 최댓값, Intraday는 `MAX(장중 고점, 마감 잔고)`의 최댓값.

웹앱의 HWM 입력 처리(2026-11-23 Instinct 검수 반영):

| 모드 | 적용 HWM | 화면 처리 |
|---|---|---|
| Intraday | `max(입력 HWM, 현재 잔고, 시작 잔고)` | 보정이 일어나면 "최고 잔고를 현재 잔고(또는 시작 잔고)로 보정했습니다" 안내 |
| EOD | `max(입력 HWM, 시작 잔고)` | 현재 잔고로 강제 보정하지 않음. `입력 HWM < 현재 잔고`이면 "EOD 마감 잔고 기준인지 확인" 경고 |

## 출금 시트 수식

| 셀 | 의미 | 수식 | 웹앱 필드 |
|---|---|---|---|
| B2 | 자격 일수 | `COUNTIF(손익, ">="&최소 일 수익)` | `days` |
| B3 | 마지막 승인 출금 이후 총 순이익 | `SUM(손익)` | `net` |
| B4 | 그 기간 가장 큰 수익일 | `MAX(0, MAX(손익))` | `largest` |
| B5 | 일관성 비율 | `IF(총순이익<=0,"계산불가", 가장큰수익일/총순이익)` | `ratio` |
| B6 | 일관성 판정 | `IF(비율<0.5,"통과","미달")` (보수적 미만) | `consPass` |
| B7 | 현재 잔고 | `시작잔고 + SUM(손익) − SUM(출금)` | `balance` |
| B8 | 잔고 요건 | `IF(잔고>=최소요청잔고,"통과","미달")` | `balOk` |
| B9 | 출금 가능 | `AND(자격일수>=5, 일관성="통과", 잔고="통과")` | `eligible` |
| B10 | 회차 상한 | `VLOOKUP(유형&크기, 상한표, 회차 열)` | `cap` |
| B11 | Safety Net 초과분 | `잔고 − (시작잔고 + Safety Net)` | `safetyExcess` |
| B13 | 실제 신청 가능 상한 | `MAX(0, MIN(회차상한, 초과분))` | `applyCap` |
| B14 | 남은 출금 횟수 | `MAX(0, 6−회차+1)` | `remainingRounds` |
| B15 | 6회 누적 상한 | 상한표 합계행(유형×크기) | `cumCap` |
| B16 | 일관성 필요 순이익 | `가장큰수익일 ÷ 0.5` | `requiredNet` |

## 웹앱 고유 계산 (엑셀에 없음)

| 항목 | 정의 | 근거 |
|---|---|---|
| 권장 1회 손실 한도 | `max(버퍼,0) × 10%` | 본편 2-6절 "1회 리스크는 버퍼의 10%" |
| MNQ 환산 포인트 | `버퍼 ÷ 2` (MNQ 1계약, 1포인트 $2) | 본편 1-4절 지표 3 |
| 평가 모드 임계값 정지 | Rithmic·WealthCharts는 목표 잔고에서 정지, Tradovate는 무정지 | 본편 2-3절 |
| 상태 신호 | 버퍼 비율 10/25/50% 구간 | 본편 2-6절 |

## 레거시 처리

- 250K·300K는 레거시 전용이라 계산기에서 제외(규격 미확인 상태에서 추정 금지).
- 일관성 30% 옵션은 판정식만 변경하며, 레거시의 8거래일 사이클·회차 상한·리셋은 반영하지 않음. 선택 시 화면에 경고 문구를 띄운다.
